# 📱 SMS Spam Detector

A machine learning web app that classifies SMS messages as **Spam** or **Ham (Not Spam)** in real time, with a confidence score.

---

## 🖥️ Demo

> Enter any SMS text → click **Analyze Message** → get an instant prediction with confidence %.

## ⚙️ Setup

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/spam-detector-app.git
cd spam-detector-app
```

---

### Option A: Run with Docker Compose (Recommended)

Requires [Docker Desktop](https://www.docker.com/products/docker-desktop/). No local Python or PostgreSQL setup needed.

1. **Configure Environment Variables (Optional):**
   Copy `.env.example` to `.env` if you wish to customize credentials (default fallbacks are already configured):
   ```bash
   cp .env.example .env
   ```

2. **Build and Run:**
   ```bash
   docker compose up --build
   ```

   This launches:
   - **`spam-web`**: The Flask application served via Gunicorn (2 workers, 4 threads) on port `5000`.
   - **`spam-db`**: PostgreSQL 16 storing prediction logs with persistent volume storage (`pgdata`).

3. **Access the App:**
   - **Web UI:** Visit [http://localhost:5000/ui](http://localhost:5000/ui)
   - **API Health:** Visit [http://localhost:5000/](http://localhost:5000/)

To stop the containers:
```bash
docker compose down
```

---

### Option B: Run Locally (Python Virtual Environment)

Requires Python 3.12+.

#### 1. Create a virtual environment

```bash
python -m venv venv
source venv/bin/activate        # macOS / Linux
venv\Scripts\activate           # Windows
```

#### 2. Install dependencies

```bash
pip install -r requirements.txt       # runtime API dependencies
pip install -r requirements-dev.txt   # API + notebook + tests
```

#### 3. Start the backend

```bash
python backend/app.py
```

The API will be available at `http://127.0.0.1:5000`.
*(Note: PostgreSQL prediction logging is automatically bypassed if `DB_HOST` is not set).*

#### 4. Open the frontend

Open `frontend/index.html` directly in your browser, or navigate to `http://127.0.0.1:5000/ui`.

If the backend runs on a different port or host, point the static UI to it with a query parameter:
```
frontend/index.html?api=http://192.168.0.10:5000
```

## 🧬 Regenerating the Model

`backend/spam_model.pkl` and `backend/vectorizer.pkl` are committed so the app runs out of the box. To retrain them, run **every cell of `notebooks/spam_detection.ipynb`** — the final cells save both artifacts into `backend/` and verify they load the same way `app.py` does.

```bash
pip install -r requirements-dev.txt
jupyter nbconvert --to notebook --execute --inplace notebooks/spam_detection.ipynb
```

> The artifacts are scikit-learn pickles and are only guaranteed to load under the scikit-learn version pinned in `requirements.txt`. Re-run the notebook after bumping it.

## 🔌 API Reference

### `GET /`

Health check endpoint reporting API, model, and database status.

```json
{
  "status": "ready",
  "service": "SMS Spam Detector API",
  "model": "loaded",
  "database": "connected"
}
```

### `GET /ui`

Serves the built-in frontend single-page interface directly from the Flask server.

### `GET /predictions`

Retrieves logged predictions from PostgreSQL (optional query parameter `?limit=20`, max 100).

```json
{
  "count": 1,
  "predictions": [
    {
      "id": 1,
      "message": "You have won a prize! Call now.",
      "prediction": "Spam",
      "confidence": 98.7,
      "model_version": "v1",
      "created_at": "2026-10-25T09:30:00"
    }
  ]
}
```

### `POST /predict`

Analyzes an incoming SMS and logs the prediction to PostgreSQL (if database configuration is active).

**Request body:**
```json
{ "message": "You have won a prize! Call now." }
```

**Response:**
```json
{
  "message": "You have won a prize! Call now.",
  "prediction": "Spam",
  "confidence": 98.7
}
```

**Error responses:**

| Status | Reason |
|--------|--------|
| 400 | Body is not a JSON object (array, string, number, `null`, malformed) |
| 400 | Missing, non-string or empty `message` field |
| 400 | Message exceeds 1000 characters |
| 503 | Model not loaded (run the notebook first) |

All error responses are JSON of the form `{ "error": "..." }` — the API never returns an HTML error page for a bad request.

## 🧠 How It Works

1. **Dataset:** UCI SMS Spam Collection — 5,572 messages, of which **403 are exact duplicates**
2. **Cleaning:** duplicates are dropped before any splitting → 5,169 unique messages (86.6% ham / 13.4% spam in the raw file)
3. **Vectorization:** Bag-of-Words via `CountVectorizer` (unigrams, lowercased)
4. **Classifier:** Multinomial Naive Bayes (`MultinomialNB`)
5. **Serving:** Flask REST API (production-ready via Gunicorn in Docker)
6. **Logging:** Optional asynchronous-safe prediction persistence to PostgreSQL via `psycopg2`

### 📊 Results

5-fold stratified cross-validation on the de-duplicated dataset — these are the numbers to quote, since a single train/test split varies by up to ~0.05 F1 depending on the random seed:

| Metric | Mean ± Std |
|--------|------------|
| Accuracy | 0.9857 ± 0.0027 |
| Precision | 0.9723 ± 0.0107 |
| Recall | 0.9127 ± 0.0150 |
| **F1** | **0.9415 ± 0.0111** |

The notebook also reports a single 80/20 split for reference (`random_state=1`): accuracy 0.9797, precision 0.9524, recall 0.8889, F1 0.9195.

- Model artifacts loading and ML inference happy paths

```bash
FLASK_DEBUG=true PORT=8080 python backend/app.py
```

## 🛡️ Security Notes

- User input is HTML-escaped before rendering in the history panel (XSS prevention)
- Message length is capped at 1000 characters on both client and server
- The API validates **types** as well as content: non-object JSON bodies and non-string `message` fields are rejected with 400 instead of crashing the request handler
- Debug mode is off by default
- In production / containerized mode, the app is served via **Gunicorn** (`2` workers, `4` threads) rather than the Flask development server
- Database errors in prediction logging are caught gracefully and will never crash or fail a `/predict` response
- **CORS is wide open** (`CORS(app)` reflects any origin) — restrict origins before exposing publicly
- Analysis history is stored only in your browser's `localStorage` (capped at 20 entries); **Clear All** removes it
- The frontend loads Tailwind from the Play CDN, which is suitable for demos but should be replaced by a compiled stylesheet in production
- `confidence` comes from uncalibrated `MultinomialNB` probabilities and tends to saturate near 100% — treat it as a ranking signal, not a calibrated probability
